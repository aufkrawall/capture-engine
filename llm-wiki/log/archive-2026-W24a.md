### 2026-06-12 - FIXED CRASH: stale Streamline hook generations on repeated OFF<->DLSS toggling (sl module unload invalidation)

- **Symptom (crash dump + logs `installed/captureengine/logs/20260612_003407`)**: toggling all-FG-off <-> DLSS FG repeatedly crashed the test app with an AV WRITE to 0xBF6A inside `sl.common.dll` on the game thread during the second DLSS enter, right after `CreateDXGIFactory1`.
- **Root cause (cdb + log proven)**: the app fully unloads and reloads the Streamline stack per OFF<->DLSS cycle. CE's Streamline hook bookkeeping was per-function-name and process-global: `g_Original_*` (gen-1 trampolines), `g_*Target` addresses, `g_*Hooked` flags, and the interposer/common install/IAT masks all survived the unload; the per-name mask dedupe then silently refused to re-hook the fresh instances ("Installed hooks for sl.common.dll" appears only once in the session). The dump shows the reloaded `sl.common.dll` (35730000-35807000) occupying the previous generation's `sl.interposer.dll` range (35760000), so the call-time `IsSavedStreamlineOriginalCallable` guard — which only checks "target belongs to a loaded module" — passed, and the stale gen-1 trampoline jumped mid-instruction into the NEW module (a CE trampoline-pool address was still live in RSI at crash time). Address-space reuse defeats call-time validation; this is the module-level analogue of the swapchain pointer-reuse lesson.
- **Fix**: event-driven + load-time self-heal. (1) `StreamlineHook::OnModuleUnloaded` (dispatched from the loader DLL-unload notification in `hook/main.cpp`, loader-lock-safe: interlocked/atomic writes + light logging) invalidates every hook slot whose patched target or saved original lies inside the departing image — original cleared FIRST so detours fail safe through the existing null-callable paths — plus the import-fallback attempted-target slots, and clears the per-module install/IAT mask bits so the next load re-hooks the fresh instance. (2) Load-time self-heal in `InstallHooksForModule`: when a core module name arrives with its mask bit set but none of the stored core targets belong to the arriving instance, the mask is a stale generation — core slots belonging to no live core instance are cleared and the fresh instance is re-hooked (covers environments where `LdrRegisterDllNotification` is unavailable).
- **Regression tests**: `StreamlineModuleUnloadDispatchesHookInvalidation`, `HookSlotInvalidationMatchesUnloadedImageRange`, `ReloadedCoreModuleMaskIsStaleWhenNoTargetBelongsToArrivingInstance` in `tests/test_streamline_runtime_policy.cpp`. Full suite 965 passed.
- **Expected diagnostics**: `Streamline Hook: Invalidated <fn> hook slot for unloaded sl.*`, `Module sl.* unloaded ... invalidated N stale hook slot(s); the next load of this name re-installs hooks`, `reloaded at ... installed-module mask refers to a previous unloaded generation`.
- **Brief overlay blanks in the same session**: CE-attributable gaps were already small — DLSS engage used the pure-DLSS clamped 8-frame cooldown (~60ms) and DLSS->OFF used the `pure Streamline FG OFF — bypassing generic reinit cooldown` immediate rebuild (~26ms to first submit). The visually longer freezes are app-side NGX init/teardown windows where the last presented frame (still containing the overlay) stays on screen. Stale-hook breakage in the crash cycle could also blank by missing `slDLSSGSetOptions` interception; fixed by the per-generation re-hooking.
- **Open hardening item**: the FFX guarded `ffxConfigure` VEH breakpoint stores a raw target address; an FFX module reload at a different base could re-arm 0xCC into re-mapped foreign memory — same unload-invalidation treatment if evidence ever lands there.
