### 2026-05-19 - GTA native-FSR OFF teardown ownership fix (build 0.1.3340 / tests 0.1.3342)

- **Input**: GTA V Enhanced DX12 logs at `installed/captureengine/logs/20260519_144449`; switching from FSR FG to all FG off crashed/terminated without a CE session `.dmp`.
- **Root cause**: CE saw repeated explicit native-FSR OFF configures (`ffxConfigure(frameGenerationEnabled=0)`) and `ffxDestroyContext`, but when the live swapchain queue returned to `origGame`, `DX12_SetSwapchainQueue` still preserved `fgRuntimeOwnsSwapchain=1` because the stale native-FG present-path latch made `ShouldSkipSeparateOverlayGpuWorkForRuntimeOwnedFrameGeneration(...)` true. The code was still waiting for a stronger OFF signal even though the explicit FFX OFF signal had already arrived.
- **Fix**:
  - Added `ShouldEndRuntimeOwnedNativeFGTeardownOnOriginalQueueReturn(...)` and wired `DX12_SetSwapchainQueue` so explicit native-FSR OFF plus original-queue return clears runtime-owned native-FG teardown when no authoritative FSR runtime remains active.
  - Disabled `ffxConfigure(frameGenerationEnabled=0)` packets no longer reinstall CE's FFX present-callback bridge. Existing bridge state is retained for any final already-in-flight callback until context destroy, but disabled configures are treated as teardown evidence.
  - Repeated native-FSR OFF event/debug logs are now throttled, and the injector logs tracked injected-process exit codes so future no-dump fast exits are visible in host logs.
  - Binary regression strings now prove the new teardown and disabled-bridge diagnostics are present in `capture_hook_x64.dll`.
- **Regression tests**: Added `DXGISharedTest.ExplicitNativeFSROffEndsRuntimeOwnedTeardownWhenQueueReturnsToOriginal` and `DXGISharedTest.FFXPresentCallbackBridgeInstallsOnlyForEnabledFrameGenerationConfigure`; extended `CrashHandlerBinaryTest.HookDllContainsLazyExecRegressionStrings`.
- **Verification**: `python build.py --skip-updates` passed (build `0.1.3340`). Focused `python build.py --no-build --run-tests --skip-updates --gtest-filter="DXGISharedTest.*Streamline*:DXGISharedTest.*Bypass*:DXGISharedTest.*PostSL*:DXGISharedTest.*FSR*:DXGISharedTest.*FFX*:DX12FGTraceReplayFixture.*:CrashHandlerBinaryTest.*:CrashDumpPolicyTest.*:StreamlineRuntimePolicyTest.*"` passed 230/230 tests (displayed metadata `0.1.3341`). Full `python build.py --no-build --run-tests --skip-updates` passed 769/769 tests (displayed metadata `0.1.3342`).
- **Manual validation still needed**: Re-run GTA V Enhanced through all pairwise FG toggles (`off -> DLSS`, `DLSS -> off`, `off -> FSR`, `FSR -> off`, `FSR -> DLSS`, `DLSS -> FSR`) with overlay visible. For `FSR -> off`, expected logs should include `Native FSR configure disabled; not installing DX12 present-callback bridge`, then `Explicit native FSR OFF plus origGame swapchain return ending runtime-owned native-FG teardown`, followed by `fgOwned=0` on the original queue and no process exit/crash.

### 2026-05-18 - GTA pure-DLSS Streamline startup transport fix (build 0.1.3314 / tests 0.1.3316)

- **Input**: GTA V Enhanced DX12 logs at `installed/captureengine/logs/20260518_084035`; there was no crash dump, but `all FG off -> DLSS FG` after loading gameplay briefly reported DLSS FG active and then settled back to no FG.
- **Root cause**: The previous fresh runtime-owned Streamline handoff bypass policy avoided the patched `dxgi!Present+0x5` crash, but it also treated runtime ownership itself as a transport hazard. In the pure-DLSS, Steam-absent, EOS-backed handoff, CE kept the logical normal Streamline route while transporting hundreds of startup Presents through the bypass trampoline (`freshRuntimeOwnedHandoffRisk=1`, `steamRisk=0`). That deprived Streamline/DLSSG startup of the normal Present traffic it needed, leaving the later startup OFF churn able to collapse the just-activated session.
- **Fix**:
  - Bypass/deep-hook trampolines now verify the resume target against clean on-disk bytes at instruction boundaries and extend past externally patched filler bytes. This prevents resuming inside `E9 ... CC ...` patched spans while still preserving lazy bypass creation.
  - `ShouldTreatStreamlineStartupNormalRouteTransportAsUnsafe` now requires a real third-party/stale Present-hook risk in addition to D3D12, non-wrapper, runtime-owned Streamline startup conditions. Runtime-owned Streamline alone is no longer unsafe transport.
  - `DetourPresent` and `DetourPresent1` keep the startup route decision intact, but allow pure-DLSS runtime-owned startup traffic to use the normal Streamline transport when Steam/stale-hook risk is absent. The Steam and post-FSR stale-risk families still use bypass transport.
  - Added diagnostics for `Streamline startup normal-route transport allowed` and retained the bypass diagnostics with `transportRisk` / `steamRisk` fields so future GTA traces can prove whether the normal-route traffic is being allowed or bypassed.
- **Regression tests**: Added/updated `DXGISharedTest` coverage for pure-DLSS runtime-owned startup transport, startup-handoff bypass reasons, post-FSR/stale-hook behavior, Present/Present1 parity, and an inline-hook policy regression for verified external-hook resume offsets. Extended `CrashHandlerBinaryTest.HookDllContainsLazyExecRegressionStrings` to prove both the verified resume and normal-route transport diagnostics are compiled into `capture_hook_x64.dll`.
- **Verification**: `python build.py --skip-updates` passed (build `0.1.3314`). Focused `python build.py --no-build --run-tests --skip-updates --gtest-filter="DXGISharedTest.*Streamline*:DXGISharedTest.*Bypass*:DXGISharedTest.*PostSL*:DXGISharedTest.*Startup*:DX12FGTraceReplayFixture.*:CrashHandlerBinaryTest.*:CrashDumpPolicyTest.*:StreamlineRuntimePolicyTest.*"` passed 203/203 tests. Full `python build.py --no-build --run-tests --skip-updates` passed 762/762 tests (displayed metadata `0.1.3316`).
- **Manual validation still needed**: Re-run GTA V Enhanced DX12 from all FG off, load into gameplay, enable DLSS FG, and apply. Expected logs should show the verified bypass resume diagnostic early if the external DXGI patch is present, then `Streamline startup normal-route transport allowed` for the pure-DLSS runtime-owned startup with `transportRisk=0` / `steamRisk=0`, followed by stable `DLSS_FG active=1` and no collapse back to `STREAMLINE_NO_FG`. Also re-check the earlier Talos/Strange Brigade Steam and GTA DLSS/FSR/off switching families.
