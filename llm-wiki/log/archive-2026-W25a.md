### 2026-06-21 - "Metallic" app-audio root-caused to config override Process-key leak (triplicated captures)

- **Why:** A Strange Brigade recording had clearly "metallic" tracks 1 & 2 (application audio) and a slightly "too light / missing bass" track 3 (system audio) — classic comb filtering, not pitch/distortion (`installed/captureengine/logs/strangebrigadeweirdappaudio/media.log`, build 0.1.4186). User confirmed track 2 has no mic, so mic mixing was ruled out.
- **Root cause (config override leak):** config had three candidate app-audio sources routed to tracks 1 & 2 — `[AppAudio.1] Process=FortniteClient-Win64-Shipping.exe`, `[AppAudio.2] Process=StrangeBrigade_DX12.exe`, `[AppAudio.3] Process=StrangeBrigade_Vulkan.exe` — plus `[App.2] Process=StrangeBrigade_DX12.exe` matching the running game. `LoadConfig`'s `GetStr` "Override Simplified" fallback (`common/config.cpp`) resolved the bare `process` key of *every* `[AppAudio.N]` from the matched `[App.2]` section's selector `Process=` key, rewriting all three app-audio sources to `StrangeBrigade_DX12.exe`. Log proof: six independent process-loopback capture clients all `Started: PID=21548`, three per track; `FindProcessByName` is exact-match so Fortnite/SB_Vulkan could only have captured SB_DX12 via the rewrite. Three independently buffered, phase-offset copies of identical audio summed per track at `mediaengine.cpp` mix → comb filter. Track 3 (single system loopback + mic) doesn't self-comb, so it was only mildly affected.
- **Secondary fidelity bug:** the mix limiter applied `s = std::tanh(s*1.2f)/1.2f` unconditionally to every sample of every track on top of a soft-knee that already bounds to (-1,1). It squashed a clean 0.9 peak to ~0.66 (ceiling ~0.695 ≈ -3.2 dBFS) and added amplitude-dependent compression/harmonic distortion to all audio incl. lossless ALAC — a plausible cause of track 3 sounding "light".
- **Fixes:** (1) `IsReservedOverrideSelectorKey` excludes bare `process`/`processname` from the `[App.N]` simplified-override fallback (explicit `AppAudio.N.process=` still works). (2) `ce::audio::ApplySoftKneeLimiter` (in `audio_sync_utils.h`) replaces the inline limiter — soft-knee only, NO global tanh, bit-exact below 0.9. (3) Duplicate-capture safeguard: `MediaEngine` Init/ReloadConfig dedupe app-audio by `ce::audio::AppAudioTrackIdentity` `(process|pid, track)`, skipping same-(process,track) duplicates with a `WARNING`; runtime per-track source summary `AudioLoop: Track N sources: [...]` + duplicate warning. (4) Diagnostics: log matched `[App.N]` override section, each resolved `[AppAudio.N]` process+tracks, and a warning when an override rewrote an app-audio process.
- **Tests:** `tests/test_config_override.cpp` — `AppAudioProcessNotRewrittenByAppSelectorKey` (fails pre-fix), `AppAudioExplicitProcessOverrideStillApplies`, `MultipleAppAudioSourcesKeepDistinctProcessNames` (Strange Brigade profile). `tests/test_audio_sync_utils.cpp` — soft-knee transparency/bounding/monotonic/empty + `AppAudioTrackIdentity` semantics. Full suite: 1082 tests / 63 suites PASS; production + tests-only builds clean.
- **Validation pending:** real Strange Brigade recording — confirm only the running game is captured once per track (Fortnite/SB_Vulkan find no process), no comb/metallic on tracks 1 & 2, track 3 no longer thin, and A/V sync / track lengths unchanged (`ffprobe`).

### 2026-06-21 - FFX UI-bundle overlay revived (GTA no-callback FSR FG invisibility)

- **Why:** GTA V Enhanced overlay went invisible the instant the game enabled native FSR FG (no app present callback) and never returned (`installed/captureengine/logs/gtanooverlay`). The overlay rendered ~4500 backbuffer frames fine, then `Overlay frame #` froze at FG-on while `DetourPresent` heartbeats kept advancing. The `dx12_fg_switch_test.exe` capture (`.../fgswitchtestapp`) only "worked" because it toggles FG **off** — the bundle fired **0** times there too, so the overlay was visible during FG-off phases, not during FG-on.
- **Root cause (two coupled defects):** (1) During no-callback FSR FG, `DetourPresent` (`hook/common/dxgi_shared.cpp:2662`) deliberately skips the backbuffer `ProcessFrame` (submitting overlay work on AMD's runtime queue freezes GTA ~900 frames) and relies on the ECL **UI-texture bundle** (`RecordBundleOverlayForGameECL`, appended to the game's own `ExecuteCommandLists`). But the bundle's GPU resources (`g_FFXUiCompositeList`/`RtvHeap`/allocators + the FFX overlay adapter) were created **only** inside `DX12_CompositeOverlayOntoFFXUiResource`, which is dead code (`DX12_ShouldCompositeOverlayOntoFFXUiResource()` hard-returns false, nothing calls it). So the bundle's null-resource guard always tripped, `RecordBundleOverlayForGameECL` returned null, and the overlay never appeared (`UI-bundle overlay appended` = 0 in BOTH apps). The silent null-return is why it hid for so long. (2) After the FFX `ffxConfigure` VEH is permanently disarmed on no-callback detection, intra-module `RegisterUiResource` calls stop being intercepted, so `g_CachedFFXUiTexture` can freeze at a startup-window pointer (stale if GTA rotates UI textures).
- **Fix:** added a LIVE lazy initializer `EnsureFFXUiCompositeBundleResources(device, gameQueue, rtvFormat, w, h)` (`hook/apis/dx12_hook.cpp`) that creates exactly the bundle-needed resources (RTV heap, 3 allocators, command list, overlay adapter) — NO separate-ECL queue/fence (the bundle rides the game's fence). `RecordBundleOverlayForGameECL` now calls it and its readiness guard requires only list+RTV heap (the old `g_FFXUiCompositeFence` requirement was unsatisfiable — only the dead path created it). The device-change branch releases GPU infra but must NOT clear `g_CachedFFXUiTexture` (would blank next frame). Never-blank routing: extracted `ce::dx12_overlay_policy::ChooseNoCallbackFSRFGOverlayRoute(cached, firing)` — `DetourPresent` only skips the backbuffer draw when the bundle is BOTH cached AND actively firing (`DX12_IsFFXUiBundleOverlayActivelyFiring()`, tick-based, 250ms window); otherwise it draws via `DX12_ProcessFrameMinimal` so the overlay never blanks across the FG-on transition (freeze-safe transient bridge — minimal stops as soon as the bundle engages).
- **Diagnostics:** `RecordBundleOverlayForGameECL` now logs every skip reason (`texture-null`/`bad-desc`/`ensure-failed`/`resources-null`); `DX12_CacheFFXUiResourceForBundle` logs the cached UI-resource pointer + change flag so a single GTA run reveals whether GTA reuses one UI texture (frozen cache fine) or rotates (needs per-frame re-cache — the deferred Defect-2 work, gated on this evidence).
- **Tests:** `tests/test_dxgi_shared.cpp` — `NoCallbackFSRFGOverlayRouteOnlySkipsWhenBundleActuallyFiring` (policy: skip ONLY when cached+firing, else draw) and `BundleOverlayRecordInitializesItsOwnResources` (source-guard: record path calls the live Ensure + uses the relaxed list+RTV-heap guard). `tests/test_stubs.cpp` stubs `DX12_IsFFXUiBundleOverlayActivelyFiring`.
- **Validation:** `python build.py --tests-only --run-tests --skip-updates --gtest-filter='DXGISharedTest.*:DXGISharedSourceTest.*'` passed; hook DLL compiles clean. End-to-end overlay-visible-during-FG-on confirmation needs a real injected `dx12_fg_switch_test.exe` / GTA run (look for `FFX UI-bundle overlay appended` > 0 and stable `Overlay`/no `uncovered streak`). NOTE: a plain `python build.py` (no `--skip-updates`) currently fails in the upstream FFmpeg rebuild after a HEAD pull — unrelated to this change; use `--skip-updates`.
- **Source anchors:** `hook/apis/dx12_hook.cpp` (Ensure helper, `RecordBundleOverlayForGameECL`, `DX12_IsFFXUiBundleOverlayActivelyFiring`, cache diag), `hook/common/dxgi_shared.cpp` (no-callback route), `hook/common/dx12_overlay_policy.h` (`ChooseNoCallbackFSRFGOverlayRoute`), `tests/test_dxgi_shared.cpp`, `tests/test_stubs.cpp`, `llm-wiki/frame-generation/{guardrails,case-studies}.md`.
