### 2026-06-22 - No-callback FSR FG UI-bundle must fire on the LIVE FG-runtime queue (test-app overlay blanked after crash-boundary change)

- **Why:** After the crash-boundary change (runtime-owned FSR FG never does the backbuffer submit), the `dx12_fg_switch_test.exe` overlay DISAPPEARED on switching to FSR FG (`installed/captureengine/logs/20260622_172043`). The crash-boundary change removed `kMinimalBackbuffer`, expecting the game-ECL bundle to cover — but the bundle never fired.
- **Root cause:** the bundle (`RecordBundleOverlayForGameECL`) only fired when `pThis == g_OriginalGameQueue`, and the no-callback ECL fast-path force-forwarded every non-origGame ECL. But once AMD's FfxFrameInterpolationSwapchain takes over, **the game submits its scene+UI on the FG-runtime-owned swapchain queue and `g_OriginalGameQueue` goes IDLE** (log: ECL heartbeat on `g_SwapchainQueue`=`...3032DD30`, `origGame`=`...2E158270` idle; `appended`=0). So the origGame-only bundle never fired and, with `kMinimalBackbuffer` gone, nothing drew.
- **Fix:** shared helper `TryAppendNoCallbackBundleOverlay(pThis, NumLists, ppLists)` whose queue eligibility is `pThis == g_OriginalGameQueue || pThis == g_SwapchainQueue` (the live FG-runtime queue). Wired into the no-callback ECL fast-path (it attempts the bundle BEFORE force-forwarding non-origGame ECLs) and the two origGame heavy-path sites (refactored to the helper). Appending to the game's OWN submission on the runtime queue is NOT a separate submit/Signal — it rides the call AMD already syncs (NumLists+1, same ECL call), so it stays within the crash boundary (unlike the removed `DX12_ProcessFrameMinimal`). Per-frame reset: `DX12_ResetNoCallbackBundleFrame()` (called from `DetourPresent`'s no-callback branch) replaces the `ProcessFrameMinimal` reset that no longer runs.
- **Tests:** `tests/test_dxgi_shared.cpp::NoCallbackBundleFiresOnLiveFGRuntimeQueueNotOnlyOrigGame` (source-guard: helper accepts both origGame + `liveFgQueue`, and is called from ≥2 ECL paths incl. the fast-path). `tests/test_stubs.cpp` stubs `DX12_ResetNoCallbackBundleFrame`. Full suite 1094 PASS; x64/x86 + test-app builds clean.
- **Verification pending:** re-run `dx12_fg_switch_test.exe` (inject) FSR-on — confirm `FFX UI-bundle overlay appended to game ECL (queue=... liveFgQueue ...)` and the overlay is visible + continuous across off↔FSR (no blank, incl. transition). Then the `--fsr-degenerate-ui` substitution path, then GTA.
- **Source anchors:** `hook/apis/dx12_hook.cpp` (`TryAppendNoCallbackBundleOverlay`, `DX12_ResetNoCallbackBundleFrame`, no-callback ECL fast-path, two origGame bundle sites), `hook/common/dxgi_shared.cpp` (`DetourPresent` no-callback per-frame reset), `hook/apis/dx12_hook.h`, `tests/test_dxgi_shared.cpp`.

### 2026-06-22 - GTA no-callback FSR FG overlay: crash boundary + CE-substituted UI texture (supersedes iteration-1 minimal-backbuffer)

- **Why:** Iteration-1 (commit `57fc052`, "Fix GTA overlay invisibility under native no-callback FSR FG") revived the ECL UI-bundle but **introduced a GTA crash** (`installed/captureengine/logs/20260621_191028`, build `0.1.4186`): `amd_fidelityfx_dx12!ffxQuery` null-deref AV (`READ from 0x8`, `mov rcx,[rsi+8]` with `rsi=0`), no CE frame on the faulting stack — AMD null-derefs because CE corrupted its presentation state. The test app tolerated it; GTA did not.
- **Root cause (two parts):** (1) **The crash** — `ChooseNoCallbackFSRFGOverlayRoute` returned `kMinimalBackbuffer` whenever the bundle was not firing, so `DetourPresent` called `DX12_ProcessFrameMinimal`, which submits overlay GPU work on AMD's runtime/swapchain queue **while AMD owns the swapchain**. ANY CE GPU work on AMD's backbuffer/runtime queue under runtime-owned no-callback FSR FG wedges/null-derefs AMD inside `ffxQuery`. (2) **Why the bundle never fired in GTA** — GTA leaves UI composition ENABLED (`flags=0x2`) but registers a **1×1 placeholder** UI texture; drawing the overlay onto 1×1 is useless and trips `list->Reset` E_INVALIDARG. The cache also froze after the one-shot VEH disarm (intra-module `RegisterUiResource` calls stop reaching `Hooked_ffxConfigure`).
- **Verified, load-bearing finding (kills the plan's Part C):** there is **no pacing-safe per-frame `RegisterUiResource` interceptor for GTA's call pattern.** For the protected AMD module, inline/export hooks fail-fast AMD, the IAT patch demonstrably does NOT catch GTA's per-frame calls (the cache froze at 2 updates the instant the VEH disarmed), and the re-armed 0xCC VEH is exactly what wedges AMD (multi-threaded contention). So per-frame substitution interception was rejected.
- **Fix (Parts A + B + D):**
  - **A — crash boundary.** `ChooseNoCallbackFSRFGOverlayRoute(runtimeOwnsSwapchain, cached, firing)` now **always** returns `kSkipBundleCovers` when AMD owns the swapchain — the overlay rides UI composition ONLY, never a backbuffer/runtime-queue submit. `kMinimalBackbuffer` survives only for the non-runtime-owned escape hatch. `DetourPresent` passes `DoesFGRuntimeOwnSwapchain() || HookHasRuntimeOwnedNativeFGPresentPath()` and has a loud defensive guard-rail that refuses any backbuffer submit under runtime-owned FG.
  - **B — CE-controlled UI texture + substitution.** The per-frame overlay refresh is the existing **game-ECL bundle** (`RecordBundleOverlayForGameECL`, fires from `ExecuteCommandLists` every frame — needs NO ffxConfigure interception), which draws onto a cached **target** texture. New `DX12_PrepareFFXUiOverlayTarget` (called from `Hooked_ffxConfigure` RegisterUiResource) decides via `ChooseFFXUiOverlayTarget`: a usable full-size game UI texture → blend the overlay onto it (test app); a **degenerate** placeholder (GTA's 1×1) → create a CE-owned **backbuffer-sized** texture (`EnsureCEUiSubstituteTexture`), **substitute** it into the forwarded desc (so AMD composites CE's texture), and cache CE's texture as the bundle target with a **transparent-clear** flag. Backbuffer geometry is cached from the FG-enable swapchain (`DX12_TryCacheRuntimeOwnedCallbackHDRStateFromSwapchain` → `g_NoCallbackBackbufferWidth/Height/Format`). The bundle clears CE's substitute to transparent each frame (only the overlay composites over the game frame); the game's own texture is never cleared.
  - **Degenerate guard.** `RecordBundleOverlayForGameECL` now **skips** (never draws onto) a 1×1/much-smaller-than-backbuffer target — fixes the 1×1 garbage/E_INVALIDARG. Blank-but-safe when no substitute is available.
  - **D — teardown.** `ReleaseFFXUiCompositeInfra` releases the CE substitute texture + resets the clear flag (teardown/device-change only, never per-frame).
- **Why AMD-safe:** the bundle writes the (CE or game) UI texture on the **game queue** as part of the game's ECL; AMD reads it on its present queue with the same game-queue→present sync the game's own HUD already rides. Zero work on AMD's runtime present queue → no `ffxQuery` wedge; post-interpolation composite → no ghosting.
- **Residual GTA-visibility risk (settled only by a GTA run):** substitution happens only on the `RegisterUiResource` calls caught **before** the VEH disarm. If GTA natively re-registers its 1×1 **every frame** after disarm, AMD's registered UI resource reverts to 1×1 and overrides CE's substitute → overlay invisible again (but still no crash). Diagnostics decide it: `SetBundleTargetTexture` logs the target + `changed` flag; `Substituted CE full-size UI texture ...` logs each substitution; the degenerate-guard skip logs loudly. If GTA registers once / rarely, substitution persists and the overlay is visible.
- **Dead code removed:** `DX12_CacheFFXUiResourceForBundle` (refactored into internal `SetBundleTargetTexture` + `DX12_PrepareFFXUiOverlayTarget`); stub dropped from `tests/test_stubs.cpp`.
- **Tests:** `tests/test_dxgi_shared.cpp` — `NoCallbackFSRFGOverlayRouteNeverSubmitsBackbufferWhenRuntimeOwnsSwapchain` (the crash regression: runtime-owned never picks the backbuffer route, all 4 bundle states) replaces the old route test; `FFXUiOverlayTargetSubstitutesForDegenerateGameTexture` (1×1 / much-smaller → substitute, full-size → composite, unknown-bb only substitutes trivially-degenerate). `BundleOverlayRecordInitializesItsOwnResources` source-guard retained. Full unit suite PASS; production (x64+x86) + tests-only builds clean.
- **Test-app substitution coverage (opt-in, default OFF — universal coverage preserved):** `dx12_fg_switch_test.exe` gains `[Stress] fsr_degenerate_ui_resource=1` / `--fsr-degenerate-ui` to register a 1×1 UI placeholder (GTA-style) instead of the full-size UI texture, so an INJECTED run exercises CE's substitution path on real AMD hardware — a synthetic proxy that isolates "does AMD composite a CE-substituted texture at all" from GTA's per-frame re-registration. Default run unchanged (full-size composite path + all existing FG-switch/stress scenarios). Placeholder is device-bound (released/recreated across FSR→DLSS→FSR). `testapp/dx12_fg_switch_{test.cpp,config.inl,fsr.inl}`.
- **Verification pending — primary acceptance is a real GTA V Enhanced FSR-FG run:** no `amd_fidelityfx_dx12!ffxQuery` crash/no new `.dmp`; `hook_debug.log` shows `Substituted CE full-size UI texture`, `FFX UI-bundle target ...`, and `FFX UI-bundle overlay appended to game ECL`; overlay visible + continuous across FG on→off→on. Compare to the `20260621_191028` crash baseline. If still invisible, the cache `changed`/substitution logs reveal whether GTA re-registers per frame (the open per-frame-override question).
- **Source anchors:** `hook/common/dx12_overlay_policy.h` (`ChooseNoCallbackFSRFGOverlayRoute` 3-arg, `ChooseFFXUiOverlayTarget`, `FFXUiOverlayTarget`), `hook/common/dxgi_shared.cpp` (`DetourPresent` no-callback branch + guard-rail), `hook/apis/dx12_hook.cpp` (`DX12_PrepareFFXUiOverlayTarget`, `EnsureCEUiSubstituteTexture`, `SetBundleTargetTexture`, backbuffer-geometry cache, bundle degenerate-guard + transparent-clear, `ReleaseFFXUiCompositeInfra`), `hook/apis/ffx_hook.cpp` (`Hooked_ffxConfigure` RegisterUiResource substitution), `tests/test_dxgi_shared.cpp`.

### 2026-06-22 - Investigated "Src 4" app-audio backlog (logs/fortip5) - NOT a bug; clarified misleading drift log

- **Trigger:** A WGC-CFR Fortnite session (`logs/fortip5`, build 0.1.4191) showed a persistent `[PullAudio] Src 4 drift: trueDrift=8821 (rb=13621 expected=4800) tier1=0% tier2=1` (~184ms over target, tier2 flag set) for the whole 6-min recording. Flagged as a possible app-audio convergence bug while triaging a faint "audio slightly delayed" perception.
- **Finding (no bug):** (1) Index confusion — `Src N` in PullAudio/STOP is the EXPANDED `audioSources[]` index, while `MediaEngine::Init setting up audio source N` is the 5-entry config index; `Src 4` = `audioSources[4]` = Fortnite→track2 (an app process targeting tracks 1+2 takes two expanded entries), not the configured `source 4`=SB_Vulkan. SB_DX12/SB_Vulkan correctly logged `app-never-started`; no wrong-process capture/comb — the metallic-fix holds. (2) ALL sources prime at ~280ms (`realBuffered=13440`) and keep it: WGC CFR never trims audio (`kWgcPreferVideoRepeatsOverAudioCuts=true`; `ShouldAllowWallClockAudioAnchor` is false for CFR), so the tier2-trim gate is always false. The logged `tier2=1` was only `ShouldActivateTier2Trim` (threshold flag), never an actual cut. (3) Benign for sync: content placed by packet QPC, `maxAudioDelta=0`, `ovf=0`, `ringUnderruns=0`, exact track lengths. A real 280ms offset would be glaring lip-sync, not "ever so slight."
- **Change (diagnostics only, zero behavior change):** `[PullAudio] Src N drift` now logs `tier2=X tier2Applied=Y` — `tier2` = drift-threshold flag, `tier2Applied` = whether a trim actually ran (always 0 in WGC CFR). Prevents re-misreading the standing startup buffer as an active trim / convergence failure. No audio/video path touched → no sync/smoothness regression risk. Full unit suite 1092/63 PASS; production build clean. (Synthetic A/V matrix intentionally not run per request.)
- **Separately (the actual faint-delay lever, unchanged):** the render→loopback probe (31.441ms here, high confidence) measures engine startup+tap, a lower bound that excludes the game's own audio write-ahead buffer, so loopback audio can land marginally late. The principled, no-regression remedy is the existing `[General] audio_capture_latency_ms` override after measuring the true offset on a real recording — not a code change.
- **Source anchors:** `mediaengine/mediaengine.cpp` (`[PullAudio] Src N drift` log + tier2 gate ~line 2758), `mediaengine/audio_sync_utils.h` (`ShouldActivateTier2Trim`, `ShouldAllowWallClockAudioAnchor`), `common/config.cpp` (`audio_capture_latency_ms` docs), `llm-wiki/multi-audio-capture.md`.

### 2026-06-22 - 192 kHz-loopback bad_alloc crash: out-of-domain WASAPI qpcPosition → unbounded silence allocation

- **Why:** `installed/captureengine/logs/capturefail` (build 0.1.4191, Fortnite session). Crash dump `crash_20260622_013615_..._pid24596_tid12776.dmp` (exception code `0x20474343` = libunwind "GCC" C++ throw) shows `KERNELBASE!RaiseException` ← `mediaengine!_cxa_throw` ← `operator new` (merged symbol `weak._Znwy...__clang_call_terminate`) ← `MediaEngine::AudioLoop`. `ub` of the throw site: `cmp r13,[rsp+0D0h]; ja length_error; shl r13,2; mov rcx,r13; call operator new` — a `std::vector<float>` ctor. At fault `r13 = 0x00000f00000025f0` = 16,492,674,426,352 **bytes** (~16.5 TB) → `bad_alloc` → uncaught → `std::terminate`.
- **Root cause:** The crashing source was the **system-audio 192 kHz loopback** (`media.log`: `Started ... rate=192000 loopback=1`, track 3, type=0). Its first packet's WASAPI `qpcPosition` (taken verbatim from `IAudioCaptureClient::GetBuffer` in `audio_capture.cpp`) was ~497 days ahead of `recordingStartSystemQpc100ns` (the video-frame QPC anchor, same 100-ns domain). `AudioLoop` computed `packetStartSamples ≈ 2.06e12` (48 kHz) → `ComputeStartupAwarePacketTimelineAdjustment` gap ≈ 2.06e12 → `std::vector<float> silence(gap*channels)` ≈ 16.5 TB. The first-packet rebase has a hole (`ComputeStartupFirstPacketRebaseOffset` returns 0 when `!sawSyncPendingPackets`), so the bogus gap was never bounded. WASAPI driver-reported QPC positions are not trustworthy and were used verbatim to size an allocation.
- **Fix 1 (root cause, capture side):** `mediaengine/audio_time_utils.h` adds `SanitizeCaptureQpcPosition(reported, now, futureTol=1s, pastTol=5s)`. `AudioCapture::CaptureLoop` now reads the live QPC after each `GetBuffer`, converts via `RawQpcToHundredNanoseconds`, and substitutes `now` for any out-of-domain position (these are universal physical bounds, not device tuning — a capture read-timestamp can't be in the future or older than the endpoint buffer). Healthy positions pass through bit-identical; raw value preserved on `AudioPacket::rawQpcPosition`; warning throttled to 8/session.
- **Fix 2 (defense-in-depth, consumer side):** `mediaengine/audio_sync_utils.h` adds `ClampTimelineGapSamplesToCapacity(gap, ringCapacitySamples)`. `AudioLoop` clamps the leading-silence gap to the ring buffer capacity before allocating (`WriteRetainNew` drops the excess anyway), so no timestamp can ever size a pathological `std::vector` even if it bypasses Fix 1. Warns when it clamps.
- **Tests:** `tests/test_audio_time_utils.cpp` — `SanitizeCaptureQpc{PassesThroughHealthyPositions,ReplacesFarFutureGarbage,ReplacesFarPastGarbage,TrustsValueWhenNoReferenceClock}` (the far-future case uses the exact ~497-day value). `tests/test_audio_sync_utils.cpp` — `TimelineGapClamp{LeavesInRangeGapsUntouched,BoundsOversizedGapToRingCapacity (the 2.06e12 crash value),HandlesDegenerateInputs}`. Full suite 1092/63 PASS; production + tests-only builds clean.
- **Validation pending:** real recording on the 192 kHz-loopback machine — confirm the `out-of-domain WASAPI qpcPosition` warning fires at most a few times at start, no crash/dump, the gap-clamp warning never fires, and A/V sync / track lengths stay sample-exact (`ffprobe`).
- **Source anchors:** `mediaengine/audio_time_utils.h` (`SanitizeCaptureQpcPosition`, `kDefaultCaptureQpc*ToleranceUnits`), `mediaengine/audio_capture.cpp` (`CaptureLoop` QPC guard, `rawQpcPosition` preserve), `mediaengine/audio_sync_utils.h` (`ClampTimelineGapSamplesToCapacity`), `mediaengine/mediaengine.cpp` (`AudioLoop` silence-gap clamp), `tests/test_audio_time_utils.cpp`, `tests/test_audio_sync_utils.cpp`, `llm-wiki/multi-audio-capture.md`.

### 2026-06-22 - Defer app-audio ring buffer allocation (idle "capture-any-game" overhead)

- **Why:** After the metallic-audio fix, a Strange Brigade run (`logs/20260621_234429`) was clean and sample-exact, but the "capture whichever game is running" profile still listed three candidate app-audio processes (Fortnite, SB_DX12, SB_Vulkan) → tracks 1 & 2. Only SB_DX12 runs; the other two each pre-allocated a full 30 s CFR ring buffer (~11.5 MB at 48k stereo) per `(process, track)` even though they never capture — ~46 MB wasted RAM for the four idle sources.
- **Change:** App-audio per-source ring buffers are now allocated lazily. `InitAudioSourceBuffers` constructs app-audio sources with a small 1 s buffer and records `AudioSource::fullRingBufferCapacityFloats`; on the source's first captured packet, `AudioLoop` grows the buffer in-place to full capacity via the new `AudioRingBuffer::EnsureCapacity` (mutex-protected, grows only while empty, never shrinks). System/mic sources keep full capacity immediately. Idle candidate processes now hold ~384 KB instead of ~11.5 MB; late-joining processes still get full capacity the instant they produce audio (late-join contract preserved). Race-free: the ring buffer is touched only by the AudioLoop thread, and EnsureCapacity locks the buffer's mutex.
- **Why not more:** Per-`(process, track)` monitor threads (~1 process snapshot/s each) remain — they are required to detect a target process appearing/exiting for the late-join contract, and are very cheap. Sharing one capture per unique process (to also cut the running game's two loopback clients to one) was considered but deferred: it needs a packet-fanout change to the consume-once `GetNextPacket` model and is higher risk for marginal gain.
- **Tests:** `tests/test_audio_ring_buffer.cpp` — `EnsureCapacityGrowsEmptyBufferAndAcceptsFullWindow`, `EnsureCapacityNeverShrinksAndIsIdempotent`, `EnsureCapacityRefusesToGrowWhileHoldingBufferedAudio`. Full suite PASS; production + tests-only builds clean.
- **Source anchors:** `mediaengine/audio_ring_buffer.h` (`EnsureCapacity`), `mediaengine/mediaengine.cpp` (`AudioSource::fullRingBufferCapacityFloats`, `InitAudioSourceBuffers` small-initial alloc, `AudioLoop` first-packet grow), `tests/test_audio_ring_buffer.cpp`, `llm-wiki/multi-audio-capture.md`.
