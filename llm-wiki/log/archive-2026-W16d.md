  4. `tests/test_dxgi_shared.cpp` and `tests/test_stubs.cpp` now cover the new alternate trust source so future changes cannot regress the distinction.

- **Why this is generic**: This is not another Talos-specific exception. It extends the same shared post-FSR trust model by recognizing that activation-edge provenance and bootstrap-topology safety are related but not identical questions. A comeback may still lack a real `OFF->ON via SetOptions` edge while already having enough safe DX12 topology evidence to leave the synthetic/bypass family. The shared routing code must accept either trust source instead of conflating “not explicitly activated” with “still topology-unsafe.”
