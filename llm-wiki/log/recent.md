### 2026-07-26 - Use sync-safe buffered history to soften WGC/DXGI encoder-overload recovery

- **Evidence / remaining roughness:** all six 4K120 DXGI/AV1-NVENC recordings in `installed/captureengine/logs/20260725_223214` retained contiguous CFR/audio endpoints, but the heaviest run emitted 85,280 repeats in 385,115 live ticks. - **Capacity gate:** recovery requires a measured end-to-end fresh-frame service EMA (including waits/copy overhead), no encoder-bottleneck or actively-too-slow state, and cost below 75% of the frame interval. Four submissions at that ceiling fit in three intervals, so the maximum four-tick burst can repay one wall-clock slot. Renewed pressure, exhausted surplus, an encode failure, or no grid-matched candidate immediately falls back to the prior held-repeat behavior.

The legacy `[EncoderThread] CFR Catchup applied using fresh frame` string remains a strict failure; safe substitutions use `[EncoderThread] WGC CFR grid-matched recovery frame`, per-window `FreshSvcEma`/`CatchFresh`, and final `[WGC CFR RECOVERY] GridFresh=... Required full verification build `0.1.5203` passed the clean product build, full native suite, all 12 Python tool self-tests, file-size/clang-tidy ratchets, and ASan/UBSan regression pass. ### 2026-07-25 - Make the clang-tidy ratchet scope-aware so a partial compile database cannot corrupt the baseline

- **Why:** the hazard recorded in the entry below was a real defect, not just a workflow trap. Reproduced on 2026-07-25: `--incremental --tests-only --run-tests --gtest-filter=...` regenerated `compile_commands.json` with 157 of 236 entries (tests plus hook/common); the following `--no-build --lint` linted only those translation units, saw far fewer warnings, and auto-folded the lower counts in (`bugprone-bitwise-pointer-cast 51->0`, `bugprone-branch-clone 26->9`, ...); the next `--verify` regenerated the full database and failed the ratchet with about 21 checks "regressed" (`bugprone-narrowing-conversions: 333 > 122 allowed`) with no source change. Recovery needed `git checkout -- tools/clang_tidy_baseline.json` and a wasted `--verify`.
- **Root cause:** `evaluate_clang_tidy_baseline()` compared a scalar per-check count against the baseline without knowing what the run had covered. `run-clang-tidy` lints exactly the compilation database, and that database is a snapshot of the last build's compilations, not a merged union — so its scope is an input the ratchet was ignoring.
- **Fix (`build.py`, `tools/clang_tidy_baseline.json`):** the baseline now carries a `scope` object listing the project-relative translation units its counts were measured over (236 today). `run_lint` derives the current scope from every `file` entry of the database; `clang_tidy_scope_gap()` reports which baseline units this run did not lint, **excluding units whose source no longer exists** so an ordinary deletion cannot freeze the ratchet. Improvements are folded in only when that gap is empty. A reduced scope logs `clang-tidy lint scope reduced: 157 translation unit(s) linted, 79 of the baseline's 236 not covered (e.g. ...)` plus a line naming the checks left unchanged, and records `clang_tidy_scope`/`clang_tidy_scope_units`/`clang_tidy_scope_unlinted` in the verification manifest. `--update-lint-baseline` exits 2 rather than writing a subset baseline. A full-scope run with new sources refreshes the recorded scope in place.
- **Increases stay fatal at every scope, deliberately:** warnings are only ever counted from translation units that were actually linted, so a count above the baseline — or a previously unseen check — is a genuine regression however small the scope was. A pre-`scope` baseline is treated exactly like an unknown scope: never auto-tightened, recoverable with a deliberate `--update-lint-baseline` after a full build.
- **Not changed:** `write_compile_commands_json()` still writes what the run compiled instead of merging with the previous database. Merging would paper over the same class of bug with stale flags and would change LSP behaviour; the scope record fixes the ratchet regardless of *why* the database shrank.
- **Coverage:** new `tools/tests/test_clang_tidy_baseline.py` (14 tests, registered as the seventh Python tool self-test and in the flake8 targets) pins scope derivation, the subset gap, no-tightening under reduced/unknown scope, tightening under full scope, deletion tolerance, scope refresh on added sources, fatal increases and new checks under reduced scope, the `--update-lint-baseline` refusal, and that the committed baseline records a full-scope record covering all six lint directories. Two of them were confirmed to fail against the pre-fix behaviour.
- **Verification:** the original repro was replayed end to end — the tests-only build again produced a 157-entry database, `--no-build --lint` logged the reduced-scope line and left `tools/clang_tidy_baseline.json` byte-identical, and the complete gate `python build.py --verify --skip-updates --concise` then passed at `0.1.5186` (316.7 s, clean build, full native suite, all seven Python self-tests, ASan/UBSan regression) with `clang_tidy_scope=full`, `clang_tidy_baseline=unchanged`, and `clang-tidy baseline: OK (1179 warning(s), none above baseline)` — the exact sequence that used to end in about 21 phantom regressions.
- **Source anchors:** `build.py` (`clang_tidy_scope_path`, `clang_tidy_scope_from_entries`, `clang_tidy_scope_gap`, `load_clang_tidy_baseline`, `write_clang_tidy_baseline`, `evaluate_clang_tidy_baseline`, `run_lint`), `tools/clang_tidy_baseline.json`, `tools/tests/test_clang_tidy_baseline.py`, `AGENTS.md`, and `llm-wiki/{build.py,known-debt,index,log/recent}.md`.

### 2026-07-25 - Stop encoder overload from permanently silencing CFR audio (adaptive ingestion reservoir)

- **Evidence:** `installed/captureengine/logs/audiodeath`, recording `r0001` (build `0.1.5180`, DXGI Duplication -> 120 fps CFR, AV1 NVENC lookahead/B-frames/multipass, deliberate encoder overload). Audio nearly died about 40 s in and never came back, yet every structural check passed: all three AAC tracks and video ended at exactly `11,888,000` samples / `247.666667 s`, `maxPacketDelta=0`, CFR coverage `29720/29720 missing=0`, `residual_samples=0`, `ratePpm=+0.00`, zero underruns/overruns/trims, clean post-mux probe, and **not one `WARNING`/`ERROR` line in the whole 3.8 MB media log**. The damage was only visible in `[STOP AUDIO TRACK]` (`realMixed=3056000/1863200/3104000` vs `fullSilence=8832000/10024800/8784000`) and `[STOP AUDIO DETAIL] overlap=` (9.36M-10.15M samples per source). `tools/analysis/analyze_capture_av.py` reported `audio=0` faults.
- **Root cause (consumer-overrun latch):** the CFR audio consumer pulls to `videoTimeline - 60 ms`; realized headroom is only `60 ms - captureDeliveryLatencyMs`. When a source's ring is short, `ShouldTreatStartedTimelineSourceShortfallAsSilence` exported silence, which advanced the exported cursor; `ResolveSourceTimelineWriteCursor` then pinned the source write cursor forward to it, and every later packet placed behind that cursor and was trimmed as timeline overlap. The exported cursor and the capture edge both advance at exactly wall rate, so the deficit could never repay itself. `[AppDiag] place` pins it precisely: healthy until 23:50:23 (`placed == writeCursor`, `writeMinusEncoded≈2079`, `overlapTotal=161`), then permanently `pendingWriteSamples=0 ringAvail=0` from 23:50:33 with `overlapTotal` growing by exactly 480,000 samples per 10 s — 100% of the real audio destroyed. `[AppDiag] consume` shows the trigger was a single ~67 ms over-consumption (`rb` 3349 -> 149 in one second). All five live sources (system loopback, microphone, both Fortnite process-loopback routes) latched within two seconds, so it was consumer-side, not producer-side. This affects inject, WGC, and `dxgi_dup` identically because they share `PullAndEncodeAudio`.
- **Fix — adaptive ingestion reservoir (`mediaengine/{audio_sync_utils.h,mediaengine.cpp}`):** the pull lookahead is no longer fixed at 60 ms. (1) **Instant hold:** a started source that is short but has placed a real packet within 400 ms is LATE, not silent, so `ShouldHoldCfrAudioPullForLateLiveSource` defers the pull and raises the reservoir by the shortfall plus margin instead of exporting destructive silence. (2) **Steady-state controller:** `AudioLoop` publishes the worst per-packet ingest headroom (`packetStartSamples - encodedCursor`, measured before the write-cursor pin) through one atomic whose `INT64_MAX` value doubles as the "no observation" sentinel; `ComputeAudioIngestReservoir` ratchets extra lookahead to keep 25 ms of headroom, caps it at 500 ms, holds on missing evidence, and decays 5 ms per 2 s only while headroom is comfortable. **Deepening is sync-neutral by construction:** it moves only WHEN samples are pulled, never WHERE a sample lands, so PTS, track lengths, mux endpoints, and playback rate are untouched. `baseTargetLatencySamples` follows the same value so the drift/backlog lane cannot fight it, and `ComputeAudioPullLatencyMs` now clamps its startup cap to at least the base (an adaptive base above 120 ms would have made `std::clamp` UB). `[A/V ZERO DRIFT WARNING]` allows a positive residual up to the accumulated extra lookahead; a cursor behind the target stays strict.
- **Bounded last resort:** if a live source is still fully overlap-trimmed for 1.5 s while the reservoir is at its cap, `ShouldResyncStarvedLiveAudioSource` re-anchors that one source by the unrecoverable deficit so live audio resumes — one content skip on that source only, logged as a WARNING and counted. Reaching it is a bug signature.
- **The failure was silent, so evidence was added too:** new `[AudioLoop] WARNING: source ingest starvation`, `[AudioLoop] WARNING: unrecoverable ingest starvation`, `[PullAudio] Late live source hold`, `[PullAudio] Ingest reservoir deepened|relaxed`, `idle=` on the gap-silence line, and per-source `[STOP AUDIO INGEST] ... starve= resync= reservoirPeakMs=`. `tools/analysis/analyze_capture_av.py` gained the `audio_ingest_starvation` / `audio_ingest_starvation_resync` strict verdicts, the destroyed-sample summary, strict log-event patterns, and a **legacy fallback** using `[STOP AUDIO DETAIL] overlap=` (>= 1 s absolute and >= 2% of the source's exported timeline) so pre-fix logs cannot pass triage either. Re-triage of the original session now reports `audio_ingest_starvation,ce_audio_timeline_fault` with `destroyed=48376521 samples (1007844.2 ms) sources=5`.
- **Deliberately not changed:** the video side. That session's runtime verdict was already `smoothnessNotMaximal=0`, `policyAddedRepeats=0`, `encoderLimitedDrops=0`, with `duplicates=9079/29719` against `sourceRepeatLowerBound=7658` — i.e. at the source/delivery lower bound. Its `excessRepeats=1421` and `delayRepeatClusterMax=102` coincide with a real mid-recording `dxgi_dup -> wgc -> dxgi_dup` backend transition and belong to a separate investigation; touching WGC/DXGI cadence policy here would risk the validated smoothness matrix for no evidence-backed gain.
- **Verification:** focused `AudioSyncUtilsTest.*`/`AudioCaptureSourceTest.*`, incremental product build at `0.1.5181` with PE/PDB verification, all native unit tests plus all six Python tool self-tests, and the clang-tidy ratchet (which tightened further; baseline folded in). Nine new policy tests plus one wired-up source-level test pin the fix. **Fresh runtime validation on a real overloaded capture is still required** — the fix is proven at policy and log-evidence level only.
- **Source anchors:** `mediaengine/audio_sync_utils.h`, `mediaengine/mediaengine.cpp`, `tests/{test_audio_sync_utils,test_audio_capture_source}.cpp`, `tools/analysis/analyze_capture_av.py`, and `llm-wiki/{cfr-capture-sync,multi-audio-capture,index,log/recent}.md`.

### 2026-07-24 - Codebase-wide quality audit: repair the fuzzing safety net, ratchet clang-tidy, remove dead error paths

- **Audit scope/result:** whole repository (248,161 lines of C++), not a single commit. No release blockers and no Critical/High defects in shipped behaviour. Build, tests (1,836 native + 6 Python), ASan/UBSan regression, PE hardening verification, and the Linux cross-compile CI job all pass, and there are zero `TODO`/`FIXME`/`HACK` markers repo-wide. The real finding was a **safety-net integrity problem**: the two gates meant to protect the untrusted-input parsers and catch memory/lifetime defects were non-functional or permanently muted.
- **Fuzzing was dead, not merely unrun (`f9c72e67`, `18d46408`):** `tests/fuzz/fuzz_ipc_deserialize.cpp` forward-declared `ce::ipc::ValidatePayload(msg, size_t)`, but the real validators take one argument, are not in namespace `ce::ipc`, and live in an anonymous namespace — so the harness could never link. `build.py` contained no occurrence of "fuzz" at all, and both seed corpora were empty directories. `llm-wiki/fuzzing.md` documented paths that did not exist and was itself an orphan page. The IPC harness now targets `ValidateProcessMessage`, the actual trust boundary, and fuzzes `bytesRead` and peer identity rather than only the message image. `build.py --run-fuzz [--fuzz-seconds N]` builds each harness against the whole `common/` tree and runs it against its committed corpus, failing closed on missing libFuzzer, unregistered harness, empty corpus, crash, or zero executed units, and recording `coverage.fuzz`. Measured: config roughly 40 exec/s (temp-file bound), IPC roughly 350k exec/s, no crashes.
- **MinGW libFuzzer/ASan wiring:** the clang driver rejects `-fsanitize=fuzzer` for `x86_64-w64-windows-gnu` even though `libclang_rt.fuzzer-x86_64.a` ships with the toolchain, so coverage flags and the archive are passed explicitly. Two ASan options are set after verifying both reports contain no project frames: `detect_container_overflow=0` (non-instrumented MSYS2 `libc++` causes false container overflows inside libFuzzer's own corpus reader) and `intercept_strlen=0` (the interceptor fires on `ucrtbase`/`ntdll` internals during driver start-up). Heap UAF/double-free/OOB detection stays enabled. Generated units go to a scratch corpus, and fuzz compilations are excluded from `compile_commands.json` so they cannot displace real product flags for `common/*.cpp`.
- **`FrameQueue::Push` dead error paths (`c172a91a`):** `Push` always moved the frame into the buffer and returned `true` unconditionally, yet both call sites branched on it. The inject ingest branch reached `qf.injectRingLease.Reset()` on an already-moved-from frame — a no-op that, had the branch ever become reachable, would have left the ring slot uncompleted and stalled the inject producer. The WGC branch cached `frame.texture` before the move and released it on the same imagined failure, a latent double-release. `Push` now returns `void` so no caller can write such a path; two regression tests pin exactly-once texture release on overflow and lease-ownership transfer.
- **clang-tidy ratchet (`69815e5b`):** 1,179 warnings ran advisory-only with no baseline, so the count never shrank and new findings were invisible among 333 narrowing conversions, 157 enum zero-inits, and 61 mutex static initialisations. `tools/clang_tidy_baseline.json` freezes accepted counts per check (not `file:line`, which would churn); the stage now fails on any increase or new check and folds improvements in automatically. Verified both directions: one added `atoi()` raised a check 42→43 and failed with exit 1; reverting restored a clean pass.
- **Empty catches (`43ea4dd5`):** three `catch (...) {}` blocks discarded real diagnostic information at genuine `noexcept` boundaries — loader-redirect resolution in `hook/main.cpp`, `QueryInterface` promotion in `dxgi_swapchain_wrap.cpp` (where Streamline/FFX proxies can throw, silently pinning an older interface version), and notified-pid recording in `process_audio_session_monitor.cpp` (where a dropped id presents as an app never producing audio). Each now emits a rate-limited diagnostic with unchanged fallback behaviour. `bugprone-empty-catch` is at zero and the ratchet holds it there.

Only `--concise`, `--verbose-commands`, `--jobs`, `--log-file`, and `--detail-log` are presentation-neutral. The intent was already present ("the complete relevant test gate is still required") but no bullet named the command that is the complete gate. `AGENTS.md` and `build.py.md` now mark the incremental and clean gates as build-only, name `--verify` as the complete gate with the categories that require it, and document the ratchet and fuzz flags.
