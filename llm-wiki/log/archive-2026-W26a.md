### 2026-06-27 - FIX: WGC abnormal old-frame/ghost judder class -> copy-pool lease/generation guard + split surface budget

- **User bug/evidence:** fresh real-game WGC session `installed/captureengine/logs/20260627_052028` (DX12 borderless VRR, 4K/120, GPU often 100%, fast p1) had abnormal visual judder/ghost-image artifacts around recording-sec 20-40 even though the game Present hook stayed smooth (max present gap about 10.842 ms) and audio/mux/encoder evidence was clean. The old log had no pool lifetime evidence, so analyzer now reports this shape as WGC/source/visual-lifetime suspicious instead of encoder or mux pressure.
- **Root cause class fixed:** the WGC retained copy pool previously had no explicit ownership token for queued, selected, buffered, last-frame, or currently encoding textures. A larger WGC playout reservoir made it possible to keep more old pool textures live, so reusing a slot without a lifetime guard risked showing stale/overwritten content that looks harsher than ordinary CFR repeats.
- **Fix:** every retained WGC texture now carries `poolSlot`, `poolGeneration`, and a move-only `WgcPoolSlotLease` from `WGCCapturedFrame` through direct callbacks, `QueuedFrame`, startup candidates, `g_FrameQueue`, `bufferedWgcFrames`, and `g_LastFrame`. `CopyFrameToPool` copies only into unleased slots. If all slots are leased, CE logs/drops the incoming WGC frame as `wgc_pool_saturated_safe_drop` instead of overwriting queued/selected/encoding content. Leases release on queue/cache drops or after `MediaEngine_ProcessFrameD3D11` returns; if media-engine WGC input ownership becomes asynchronous, this must be extended to a GPU completion fence. Pool generations make stale releases harmless after a pool recreate.
- **Budget/sync fix:** WGC source frame-pool buffers and CE copy-pool slots are now budgeted separately under `wgc_smoothness_buffer_vram_budget_mb` (default 2048 MB). The budget reserves source buffers first (default 8, min 3), then sync-delay frames and 4 safety slots, then extra smoothness frames. At 4K FP16/120 with the default budget the expected shape is about 8 WGC source buffers plus 24 copy-pool slots, leaving about 16 extra smoothness frames after sync/safety. The smoothness extra delay is selected at startup only and applied to the shared audio/video anchor; later WGC deficits become CFR repeats with clear source/budget attribution, not live audio retiming.
- **Diagnostics/analyzer:** `[WGC Perf]` and smoothness summaries now log source frame-pool buffers, copy-pool slots, budget surfaces, sync/extra/safety frames, leased max/free min, saturated safe drops, overwrite-prevention skips, lease mismatches, and cap-limited state. `tools/analyze_capture_av.py` has `--recording-window START:END` alignment and verdicts for `wgc_pool_slot_lifetime_fault`, `wgc_pool_saturated_safe_drop`, and `wgc_pool_evidence_missing`; false encoder/mux attribution is suppressed unless overload flags, mux backpressure, or wait times prove it.
- **Validation:** `python tools\analyze_capture_av.py --self-test` passed. The required build passed (`python build.py --skip-updates`, build 0.1.4309). The required test-only run passed (`python build.py --no-build --run-tests --skip-updates`, 1157 native tests plus Python self-tests; displayed metadata 0.1.4310). `tools\analyze_capture_av.py --session-dir installed\captureengine\logs\20260627_052028 --recording-window 20:40` classifies the old log as missing WGC pool evidence with clean audio/mux/encoder pressure rather than proving encoder overload.

### 2026-06-25 - FIX (iter 4): the whole inject-parity Bresenham pacer was the wrong model → replace with fixed-latency nearest-target jitter-buffer playout

- **The iter-3 setpoint depth-cap (build 0.1.4277) did NOT fix it.** Real session `logs/20260625_180512` (Strange Brigade 4K WGC, 10-bit, avDelay=29.8ms, fast p1, GPU~100%, VRR borderless, av1_nvenc) still had harsh abnormal stutter in recording sec 20-50 with the **game render provably smooth there**. Decisive new evidence from the in-game present hook (`perf_metrics_11800.csv`, the game's own DXGI Present timing): 7276 presents in sec 20-50, avg 4.1ms (~242fps present rate), **max present interval 10.5ms, ZERO gaps >12ms**, frametime stddev 723us. So the game never hitched; the stutter is entirely in the WGC capture pipeline.
- **Two layered root causes:**
  - **(Layer 1, inherent) WGC frame *delivery* is bursty/gappy under GPU-bound VRR borderless.** DWM hands frames to the capture frame pool irregularly: `[WGC Perf]` shows delivery dipping to `MinIn250=24..110` with `JitMax=174ms`/`CbGap=203ms` even though the game presents at 242fps with 10.5ms max interval. The inject path taps the game's real per-present stream and avoids this entirely; this is a WGC/DWM-vs-independent-flip limitation, not a CE bug.
  - **(Layer 2, the bug) the oldest-first Bresenham pacer AMPLIFIED that delivery jitter into harsh stutter.** The count-based depth cap **bulk-dropped** a whole delivered burst in one tick (`depthBefore=10/12/16` trimmed to 6) and then the buffer ran dry across the following lull, so a ~115fps source produced `tickDup≈20` **AND** `dropObs≈14` in the **same second** (drop+dup churn — far harsher than uniform CFR judder). And oldest-first emission **rubber-banded** the realized delay: `[WGC CFR SMOOTHNESS DELAY] realizedDelayMin=0us..Max=243369us` vs 29.8ms target (`DupPct=8.0%`, `longestDup=47`=391ms freeze). Analyzer: `wgc_active_delay_realized_delay_unstable,wgc_av_sync_delay_residual` (residual_max=213.5ms). Audio clean (`ratePpm=+0.00`, equal durations).
  - **Why iter-1/2/3 all failed:** they all kept the count/oldest model. A count-based reservoir + oldest-first emit fundamentally cannot reconstruct smooth CFR from bursty delivery — the realized delay = oldest-frame age, which swings with batch composition.
- **Fix (iter 4):** replace the Bresenham count/oldest pacer with a **fixed-latency jitter-buffer playout** (`DecideWgcNearestPlayout` + `ShouldDropWgcFrontForNearerPlayout`, `capture_pipeline_policy.h`). Each output tick selects the buffered frame **nearest the grid playout target** `computeDelayedWgcSelectionTargetQpc` (= `gridTick − contentDelay`, **unclamped** so low-source/recovery doesn't collapse the delay): drop frames the audio timeline already passed (older than target when a closer not-too-new successor exists; `playoutLeadToleranceQpc = GetWgcActiveDelayResidualToleranceQpc`), emit the slot frame once aged in, else hold (even source-limited repeat) keeping newer frames as reserve. This **consumes at the source rate by construction** (no over-drain, no clustered "too-new" holds like the old grid-rate timestamp reservoir; no bulk-dump churn), **pins the realized delay near `contentDelay`** regardless of delivery burstiness, and after a true gap resumes by **dropping the audio-passed backlog** (not replaying it → no rubber-band; the in-gap freeze stays clean). Jitter within the ~30ms budget is fully absorbed; jitter beyond it still forces even holds (unavoidable at a 30ms budget; deeper adaptive A/V buffer is a future option the user deferred).
- **Logging:** retired `[WGC CFR] active-delay reservoir over target` → `[WGC CFR] active-delay playout catch-up: dropped N audio-passed frame(s) after a WGC delivery gap ... NOT a game render hitch` (throttled, ≥3 drops). `delayPaceCapTrim` now counts age-based playout catch-up drops. Retired the now-unused `wgcDelayCreditAccumulator`.
- **Inject:** confirmed **structurally immune** and left as-is — it already selects nearest-to-delayed-grid (`SelectFrameClosestToGridIf` + `ComputeDelayedContentGridStartQpc`, `idealQpc = nowQpc − contentDelay`) over an abundant per-present (non-batched) stream, and decimates one-at-a-time (no bulk dump). Regression-locked by a new test proving its realized delay stays pinned even with an abundant buffer (where oldest-first would give ~2x delay).
- **Validation:** build clean (0.1.4283); 1146/1146 unit tests + Python self-tests. New tests: `WgcNearestPlayoutDropsAlreadyPastFramesForCloserSlot`, `WgcNearestPlayoutEmitHoldDecision`, `WgcNearestPlayoutAbsorbsDeliveryJitterWithinBudget` (smooth source + within-budget bursty delivery → 0 holds, pinned delay), `WgcNearestPlayoutEvenHoldsAndStableDelayUnderGapBeyondBudget` (gap>budget → bounded delay, no drop+dup-same-tick, holds bounded by gap), `FrameTimingUtilsTest.InjectDelayedGridSelectionPinsRealizedDelayUnderAbundantBuffer`. **Needs real-game soak (WGC + inject)** — runtime smoothness is the required proof: watch `realizedDelayMin/Max` tight (~25-40ms not 0..243ms), per-second `tickDup` without simultaneous `dropObs`, no `wgc_active_delay_realized_delay_unstable`. `DecideWgcActiveDelayPace`/`GetWgcActiveDelayPaceMaxDepthFrames` kept as tested building blocks but retired from production.
