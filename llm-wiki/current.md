## Current Logging Model
- `config.ini` now supports `log_level=none|off|error|warn|info|debug|trace`.
- `debug` is the normal debugging level and should be the default for day-to-day diagnosis.
- `trace` is the forensic level for very verbose internals such as inline-hook byte dumps and the per-frame CSV perf logger.
- `none` and `off` are equivalent: both map to `LogLevel::Off`. When `Off`, `IsAnyLoggingEnabled()` returns `false`, and the engine skips all debug machinery — no `logs\` directory is created, no session subfolder, no `session_manifest.txt`, no crash handler/minidump setup, no logger service process, no hook-side log directory creation. This is the maximum-performance mode with zero debug overhead.
- Legacy `debug_logging=true/false` still works as a compatibility input and maps to `debug` / `off`.
- Legacy `perf_metrics_logging=true` still works as a compatibility input and escalates to `trace`.

- `FindAndWrapPreExistingSwapchains()` in `hook/apis/dx12_hook.cpp` was a no-op that relied on inline Present hooks being installed eagerly. When `ShouldDeferEarlyDX12TempSwapchainPresentHookInstall()` defers Present hook installation (because a third-party overlay like `nvspcap64.dll` is loaded before the first real D3D12 device), AND the game has already created its swapchain during the injection wait window, Present hooks remain permanently missing and the overlay never renders. This affected 64-bit apps where the injector waited 1000ms for D3D12 init while the game created its swapchain. The 32-bit path was unaffected because `nvspcap64.dll` is 64-bit only and never triggered the deferral. The fix (2026-05-01) makes `FindAndWrapPreExistingSwapchains()` detect missing Present hooks and retry the temp-swapchain installation at the end of `Init()`. Build `0.1.2723` confirmed with all 668 tests passing.

## Multi-Audio Capture
- `[Audio.N]` and `[Microphone.N]` sections (N=1..8) are now supported, following the `[AppAudio.N]` pattern. Each creates a separate `AudioCapture` instance with its own device. Codec/bitrate/sample_rate/bit_depth/downmix inherit from the global `[Audio]` section. Legacy `[Audio]` and `[Microphone]` sections remain backward compatible. When `[Audio.N]` sections exist, the legacy `[Audio]` is only added if it explicitly sets `enabled=true`. See `llm-wiki/log/recent.md` (2026-05-15), `common/config.cpp:1201-1310`, `mediaengine/audio_capture.cpp:63-98`.
- Device selection in `AudioCapture::Start()` now actually uses the `deviceId` parameter: first tries `GetDevice()` by opaque WASAPI ID, then falls back to friendly-name matching via `EnumAudioEndpoints()` + `PKEY_Device_FriendlyName`, then falls back to `GetDefaultAudioEndpoint()`.

## Current Hot Areas
- GTA V Enhanced all-FG-off -> DLSS FG startup uses a retained Streamline startup activation swapchain to avoid starving PostSL when startup transport must bypass before `ProcessFrame` sees the runtime-owned swapchain. Runtime-owned Streamline by itself is not a transport hazard: pure-DLSS startup should stay on normal Streamline Present transport unless Steam or another stale/fragile Present hook risk is present. Native FSR startup has a separate official-AMD rule: before direct enabled FFX API proof, CE protects official AMD FFX swapchain creation as pass-through and must not refresh Present hooks, claim the queue, inspect the AMD FFX export table, or tear down Streamline/PostSL yet. That protected pending state still counts as runtime-owned for a first disabled startup-arming `ffxConfigure(frameGenerationEnabled=0)`, so the packet preserves authoritative FSR state but is forwarded unmodified; CE installs the FFX present-callback bridge only on a real enabled configure. If no direct configure ever becomes visible but real ProcessFrame/ECL progress proves the runtime has survived startup, CE finalizes the protected path without direct API proof and allows normal overlay fallback after the FFX present callback is considered stalled. Useful diagnostics are `Streamline startup normal-route transport allowed`, `Streamline startup normal-route bypass`, `Extended resume offset past patched fill bytes`, `Protected official FFX startup swapchain pass-through`, `Finalizing protected official FFX startup pass-through after enabled ffxConfigure`, `Finalizing protected official FFX startup pass-through after sustained frame progress`, `progress-resolved official FFX runtime-owned Present path assumption`, and `Native FSR disabled startup-arming configure forwarded without CE present-callback bridge`.
- External dump handling is now storm-aware and has a narrow fatal-exit fallback. Mirrored external dumps and supplemental CE dumps are written through `.inprogress` paths and renamed only after a non-empty successful write, mirrored filenames include a short source-path hash to avoid collisions, repeated strong signatures are suppressed after one mirror plus one supplemental dump, and only a repeated strong external crash storm can force a one-shot process termination. The hook DLL also captures at most one pre-termination supplemental dump for current-process crash-like fail-fast/termination exits such as `0xC0000409`; normal exits and CE's own dump-storm termination code are ignored. The dump guard uses IAT/dynamic hooks plus inline hooks for exports such as `RaiseFailFastException`, `TerminateProcess`, `ExitProcess`, `RtlExitUserProcess`, and `NtTerminateProcess`, with `FatalExitDump: Installed inline pre-termination hook` proving the lower-level path is active. Freeze-watchdog dumps are one-shot per run and use temp/rename, but ordinary freeze dumps still do not force-kill the game.
- D3D11 forced AF on Blackwell now uses shader-aware pixel-stage gating and draw-time reconciliation. `CreateSamplerState` no longer enables AF-on blindly; runtime paths track logical original samplers, SRVs, and active pixel shader metadata, then reconcile pixel samplers only at dirty draw boundaries. AF is forced only when the active pixel shader uses implicit `sample` without explicit sample opcodes and every sampled texture register is bound to a safe mipmapped `Texture2D` SRV; `sample_b` and `sample_l` remain tracked but are not currently force-AF eligible. BioShock/UE3 needs per-context bootstrap plus a returned wrapped immediate context because temporary devices can consume process-wide bootstrap state and cached draw pointers can bypass vtable hooks. Wrapped contexts must guard wrapper-to-real forwarding so raw vtable hooks do not run a second AF tracker on the same real context. Expected validation proof is `Wrapper: AF draw hook hit`, `Wrapper: AF sampler bind tracked`, lower wrapper bind/reconcile churn, and `Wrapper: AF allow` / `Wrapper: AF reconciled` or detailed resource-skip logs without matching raw `DX11: AF allow` lines for wrapper-origin calls. See `dx11-forced-af.md`.
- Graphics override diagnostics now make `backbuffer_count` creation-time behavior visible. D3D11 `CreateDeviceAndSwapChain`, factory `CreateSwapChain`, and `CreateSwapChainForHwnd` paths log requested/actual buffer counts; DX12 real-swapchain refresh logs actual buffer count when an override is configured. `cpu_prerender_limit=1` in BioShock may fail `SetMaximumFrameLatency(1)` with `0x887A0001`, but the DX11 manual query-ring fallback is active when logs show `Created manual prerender query ring buffer` plus `Prerender buffered wait lookback=1`.
