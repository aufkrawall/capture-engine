- **WGC exact-stop/live-scheduler rule:** live debt beyond the normal `250 ms / 32 frame` window is handled while recording by scheduler rebase plus source holds/drops. Under healthy-source encoder/mux pressure, WGC uses a tighter encoder-limited near-live window of about `50 ms / 3 frames`, must not select WGC source timestamps backward, and logs a strict policy warning if recovery says encoder-limited while smoothness mode is suppressed without true source starvation. WGC generic stop drain is disabled and pending/post-stop WGC frames are discarded; `wgc_stop_hold_repeats`, WGC drain duplicate summaries, repeated too-new holds, selected-source backtracking, or large encoder-pressure phase sawtooth are validation failures. See `wgc-capture.md` and `cfr-capture-sync.md`.

- **D3D11 forced AF / wrapper path:** shader-aware pixel-stage gating and draw-time reconciliation are required. Wrapped contexts must guard wrapper-to-real forwarding so raw vtable hooks do not run a second AF tracker on the same real context. Context wrappers must also cache every inherited real context interface independently: `dx11_test.exe` draws its moving rectangle through `ID3D11DeviceContext1::ClearView`, so advertising Context1 while `m_pReal1` is null makes the app render only background under inject/overlay. See `dx11-forced-af.md`.
- **Audio/CFR sync:** audio/video tracks must remain same-length and in sync. Settled CFR audio pulls are sample-exact to the current CFR target; `[A/V ZERO DRIFT WARNING]` is a strict audio timeline fault, not a cosmetic diagnostic. Render-domain A/V delay is auto-detected by the product-safe audio-only render→loopback probe, cached only in process memory, and applied only by delaying video; CE must not create `audio_latency_cache.ini`, write measured delays to `config.ini`, or use the removed visible calibration/window-flash path in product startup. WGC treats the measured delay as a video-content reservoir: startup may wait briefly before live output, selects a delayed post-barrier reserve candidate when possible, keeps newer reserve frames, uses max-rate capture recovery when the reservoir drops below low-water, and records realized delay/residual statistics. Any startup schedule offset is diagnostic only and must not be fed back as extra steady-state selection delay because that creates repeat clusters/judder. Live active-delay selection scores strict versus bounded relaxed candidates by timestamp error, repeat-cluster cost, and rolling residual headroom; it may spend bounded residual to avoid visibly extending repeat streaks, but it rejects candidates beyond the hard late-residual limit or when avg/p95/late residual headroom is already exhausted. Severe source stalls open a short source-recovery attribution window so unavoidable reserve holds are not mislabeled healthy CE policy. Analyzer triage separates true `wgc_av_sync_delay_unrealized`, strict `wgc_av_sync_delay_residual`, minor `wgc_sync_delay_reserve_pressure`, and strict `wgc_sync_delay_policy_fault`; source-starved WGC runs with bounded avg/p95/late residual are good-ish source-limited references, but mixed source/policy pressure is still a CE visual/sync fault when policy holds are large enough. Every recording should log `[AVSyncProbe]`, `[AVSyncAuto]`, `[AVSyncApply]`, and `[WGC CFR SMOOTHNESS SUMMARY]` evidence or an explicit low-confidence reason. CFR source-clock compensation has an about-80 ms deadband and should not chase ordinary buffer deficit; healthy strict runs stop with `ratePpm=0`, `compDelta=0`, `sat=0`. App-audio that produced pre-start process-loopback packets is strict for bootstrap and must not encode a leading silent head. A process-loopback source that first becomes active late joins at the current track cursor and trims stale backlog; exact final durations are not enough if decoded content or logs show late-source replay. Duplicate source routing is supported, including the same app source recorded to multiple pure/mixed tracks; sparse started app sources contribute source-local silence instead of stalling the exported track, and analyzer triage reports them as `sparse_app_source_silence` rather than strict audio timeline faults when stop-source evidence shows no active ring content. Writer finalization and post-mux probing are separate: mux close must complete first, a probe timeout is bounded validation evidence, and shutdown must not block later captures. Live source underruns (`forceDrain=0`) remain strict unless stop-source evidence proves the source was sparse/inactive; stop-tail padding (`forceDrain=1`) is diagnostic only when decoded content and final durations are clean. Multi-system, microphone, app-audio, codec padding/finalization, and drift handling details live in `multi-audio-capture.md`, `wgc-capture.md`, and `cfr-capture-sync.md`.
