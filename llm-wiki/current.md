## High-Signal Current Items

- **dx12_fg_switch_test super resolution (2026-06-11):** per-mode upscalers (OFF->TAA/TAAU, DLSS FG->DLSS SR, FSR FG->FSR 3.1 upscale) with configurable resolution scale (`[Upscaling]`, default Quality 66.7%), FP16 linear scene/upscale chain + dithered present blit (fixes DLSS SR banding), jittered projection with per-runtime jitter plumbing. KEY TRAP: FFX `FfxApiResource.state` is NATIVE D3D12 states for frame-interpolation-swapchain resources (HUDLessColor/UI) but FFX flags for dispatch inputs — mixing them up AVs the NV driver on AMD's FG worker. See `frame-generation/guardrails.md` and `log/recent.md` (2026-06-11).
- **Streamline Reflex/DLSS-G invariant (test app, 2026-06-10):** Reflex must stay `eLowLatency` for as long as the DLSS-G proxy swapchain presents — including suspended FG (the proxy's pacer keeps running; Reflex `eOff` under it hangs the GPU within ~100 frames, DRED-proven). Reflex genuinely turns off only with the proxy teardown when leaving DLSS mode (`dx12_fg_switch_test.exe` DLSS→OFF now recreates a native swapchain). See `frame-generation/guardrails.md` and `log/recent.md` (2026-06-10).
- **x86 DX12 overlay crash/freeze is fixed as of build `0.1.3822`.** The 32-bit `dx12_test.exe` no-vsync DEVICE_HUNG was isolated to overlay text draws that sampled CE-owned font resources. x86 DX12 text now renders as native solid glyph-span geometry, while the overlay remains direct native DX12. No pseudo overlay, DirectPresent overlay, D3D11On12, sleeps, or focus-transition copy fallback are part of the fix. Start with `handoff-dx12-32bit-crash.md`; chronology is in `log/recent.md` (2026-06-09).
- **DX12 focus/fallback policy:** focus changes must not hide an otherwise drawable overlay. Truly non-presentable swapchains (occluded/iconic/zero-sized) still hold backbuffer work. The current marker is `DX12 focus-loss sync policy=v13 draw-every-frame + x86 solid-span text + upload-slot per-frame fence`.
- **DX12 third-party/FG coexistence remains topology-driven.** Steam/Rockstar/EOS/Streamline/FFX handling should be based on observed module, queue, swapchain, runtime, and callback state, not game-specific branches. See `dx12-overlay-third-party-coexistence.md`, `frame-generation/guardrails.md`, and `frame-generation/case-studies.md`.
- **WGC exact-stop/live-scheduler rule:** live debt beyond the normal `250 ms / 32 frame` window is handled while recording by scheduler rebase plus source holds/drops. Under healthy-source encoder/mux pressure, WGC uses a tighter encoder-limited near-live window of about `50 ms / 3 frames` and emits `wgc_encoder_limited_judder` triage evidence if cadence still wobbles. WGC generic stop drain is disabled and pending/post-stop WGC frames are discarded; `wgc_stop_hold_repeats` or WGC drain duplicate summaries are validation failures. See `wgc-capture.md` and `cfr-capture-sync.md`.
- **A/V sync harness is now the strict oracle for CFR capture changes (2026-06-13):** `tools/run_av_sync_matrix.py --fast-zero-drift` is the normal quick gate: fullscreen/topmost, tear-free dual-lane `dx12_av_sync_test.exe`, scenario-local CE log snapshots, WGC+inject representatives, ALAC/AAC, 60/120 fps, strict system/app tracks, CE zero-residual sample accounting, and short MKV content analysis. Use `--codec-finalization-pass`, `--short-stress` (including WGC p5 overload stress), `--full-matrix`, or `--long-soak` for broader confidence. Final green full matrix before the fast gate: `installed/captureengine/avsync_runs/20260612_200944`; fresh quick gate `installed/captureengine/avsync_runs/20260613_173216`, targeted WGC p5 run `installed/captureengine/avsync_runs/20260613_173506`, and short all-codec WGC finalization pass `installed/captureengine/avsync_runs/20260613_174306` passed after the latest hardening. See `cfr-capture-sync.md`, `multi-audio-capture.md`, and `regression-testing-and-logging.md`.
- **D3D11 forced AF / wrapper path:** shader-aware pixel-stage gating and draw-time reconciliation are required. Wrapped contexts must guard wrapper-to-real forwarding so raw vtable hooks do not run a second AF tracker on the same real context. Context wrappers must also cache every inherited real context interface independently: `dx11_test.exe` draws its moving rectangle through `ID3D11DeviceContext1::ClearView`, so advertising Context1 while `m_pReal1` is null makes the app render only background under inject/overlay. See `dx11-forced-af.md`.
- **Audio/CFR sync:** audio/video tracks must remain same-length and in sync. Settled CFR audio pulls are sample-exact to the current CFR target; `[A/V ZERO DRIFT WARNING]` is a strict audio timeline fault, not a cosmetic diagnostic. CFR source-clock compensation has an about-80 ms deadband and should not chase ordinary buffer deficit; healthy strict runs stop with `ratePpm=0`, `compDelta=0`, `sat=0`. App-audio that produced pre-start process-loopback packets is strict for bootstrap and must not encode a leading silent head. Duplicate source routing is supported, including the same app source recorded to multiple pure/mixed tracks; sparse started app sources contribute source-local silence instead of stalling the exported track. Writer finalize timeout is a strict mux ownership fault and must not fall back to a second synchronous trailer write. Live source underruns (`forceDrain=0`) remain strict; stop-tail padding (`forceDrain=1`) is diagnostic only when decoded content and final durations are clean. Multi-system, microphone, app-audio, codec padding/finalization, and drift handling details live in `multi-audio-capture.md`, `wgc-capture.md`, and `cfr-capture-sync.md`.
